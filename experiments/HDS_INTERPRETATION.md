# Поиск по гипотезам против эволюции программ: интерпретация (`hds-doc`, `hds-stream`)

Исходные данные: `experiments/hds-doc/REPORT.md`, `experiments/hds-stream/REPORT.md`, по две реплики на домен,
аудит на 100 закрытых задачах, реальная модель через Claude Code. Протокол заморожен до запуска
(`prereg.json`), после запуска генераторы миров, критерии и пороги не менялись.

## Итог одной строкой

Переход между алгоритмическими подходами зафиксирован в одной реплике из двух в каждом домене, но
преимущество поиска по гипотезам над эволюцией программ **не доказано**: в домене накладных разницы нет,
в домене сессий результат не воспроизвёлся.

## Шесть вопросов

**1. Какие принципиально разные гипотезы были сформированы?**
В каждой реплике 4 исходные и 2–3 производные (всего 6 в `hds-doc`, 7 в `hds-stream` на реплику).
Накладные: построчное восстановление по «шумному каналу»; глобальная Viterbi-сегментация потока токенов;
лучевой поиск с ограничением по суммам секций; локальный поиск по нарушениям ограничений; генерация истины
и выравнивание; EM-калибровка канала; замыкание по уравнениям.
Сессии: жадный онлайн-трекер; лучевой поиск по совместным состояниям; покрытие путями через min-cost
назначение; локальный поиск по вектору назначений; лагранжева декомпозиция по сессиям; стягивание
фрагментов; распространение от уверенных событий.

**2. Какие реально реализованы?**
Все: каждая гипотеза получила хотя бы одну работающую программу (11 программ из 11 в каждой реплике).
Различие не только в названиях: число кластеров кода в режиме гипотез 6 / 5 / 8 / 7 против 2 / 4 / 6 / 3 у
эволюции программ; среднее попарное сходство кода ниже в трёх репликах из четырёх (в `hds-stream` rep0
одинаково).

**3. Какие прошли проверки?**
Работоспособность — все. Лидером на отборочной выборке стали: рекомбинация H0+H2 (doc rep0), исходная H2
(doc rep1), рекомбинация H3+H1 (stream rep0), исходная H1 (stream rep1).
Метка «механизм уступает» (две независимые реализации значимо ниже лидера) получена четыре раза.
Остальные проигравшие гипотезы имеют одну реализацию и помечены как «идея и реализация не разделены» —
они не опровергнуты.

**4. Какие были объединены в новые решения?**
По одной рекомбинации на реплику. В двух случаях она сразу стала лидером и осталась им:
doc rep0 (+0.045 на отборе, значимо) и stream rep0 (+0.010, значимо). В двух других рекомбинация оказалась
не лучше лидера.

**5. Возникло ли улучшение, не являющееся локальной модификацией исходного алгоритма?**
Формально да, в двух репликах: итоговая программа реализует другую гипотезу, сходство кода с исходным
лидером 0.36 (doc) и 0.60 (stream), прирост на аудите значим. Оговорки существенные:
- `hds-doc` rep0: исходным лидером была слабая первая реализация H0 (0.848 на аудите). Вторая независимая
  реализация той же H0 дала 0.927 — всего на 0.007 ниже итоговой рекомбинации (0.934). Большая часть
  прироста +0.086 объясняется качеством реализации, а не сменой подхода.
- `hds-stream` rep0: сходство кода 0.5999 при пороге 0.60 — на самой границе. Чистая H1 (лучевой поиск)
  набрала на аудите 0.949 против 0.954 у гибрида; эта разница не проверялась и выглядит малой.
- Все шесть «разворотов» (pivot — новая гипотеза при застое) оказались хуже лидера, пять из них значимо.
  Переходы произошли только через рекомбинацию уже имевшихся идей, а не через обнаружение нового механизма.

**6. Доказано ли преимущество нового метода над прежним?**
Нет. G1 выполнена в одной реплике из четырёх. В домене накладных эволюция программ достигла того же
качества (0.932 / 0.932 против 0.934 / 0.929) и сама дала прирост +0.06 от своей исходной точки.
Способность преодолевать застой не лучше: выходов из застоя у программ 0 / 1 / 1 / 0, у гипотез 0 / 1 / 0 / 0.
Подтверждено только большее структурное разнообразие режима гипотез; в качество оно не конвертировалось.

## Ограничения

- Две реплики на домен: «смешанный» вердикт означает одно совпадение и одно несовпадение, не более.
- Потолок близок: исходные программы набирают 0.85–0.96, запас для различения режимов мал.
- Диагностика в домене накладных была слабой: по поведению разные гипотезы статистически не различались
  (p = 0.27), различался только код.
- Причины потерь, названные моделью при доработке, почти все остались непроверенными предположениями.
- Первая попытка сравнения оборвалась из-за отказа вызовов модели; логи сохранены в `rep0.aborted/`.
  Аудиторная выборка в ней не использовалась, прогон повторён с нуля без изменения протокола.
